# Project Map

This file maps the repositories by role rather than by chronology.

## Ground

### Axioms

**Role:** mathematical kernel.

**Question:** can the operation be applied recursively while preserving the same witness/evidence contract?

**Boundary:** implementation convenience cannot substitute for mathematical justification.

## Evidence

### Eggy

**Role:** experimental and implementation evidence bank.

Contains successful witnesses, failures, movement traces, compatibility artifacts, and historical implementations.

**Boundary:** retained behavior is evidence, not automatically law.

## Translation / systems

### Language Network

**Role:** continuity across unlike native systems.

Tracks movement through people, conversations, time, work, projects, sources, tools, and external internet surfaces without forcing all of them into one schema.

**Boundary:** local systems keep native state; cross-layer continuity comes from preserved relational ancestry.

## Portfolio rule

A repository should have a legible job.

When a branch grows enough to have a different witness contract, audience, or failure surface, it should become a separate project rather than expanding one repository indefinitely.

The collection should expose the larger system without requiring a reader to understand the entire system before any individual project makes sense.
